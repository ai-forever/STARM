# HTTP inference API

HTTP-сервис для поднятия обученного в этом репозитории чекпоинта или чекпоинта с Hugging Face Hub
в [следующем формате](https://huggingface.co/sapientinc/HRM-checkpoint-sudoku-extreme).

🇬🇧 [README на английском](./README.md) | 🇨🇳 [README на китайском](./README_zh.md)

## Быстрый старт

```bash
pip install -r api/requirements.txt
./host_model --path_directory checkpoints/<project>/<run> --port 8080

curl -s localhost:8080/generate -d '{"task": "sudoku", "input": "53..7....6..195....98....6.8...6...34..8.3..17...2...6.6....28....419..5....8..79"}'
```

`./host_model` — обёртка над [`api/host_model.py`](./host_model.py); флаги у них одинаковые:

| Флаг               | Назначение                                                                                     |
|--------------------|------------------------------------------------------------------------------------------------|
| `--path_directory` | Директория прогона, файл чекпоинта или идентификатор репозитория на Hugging Face               |
| `--port`, `--host` | Где слушать; по умолчанию `8080` на `0.0.0.0`                                                  |
| `--device`         | `cuda:1` или просто индекс                                                                    |
| `--seq-len`        | Длина последовательности, если её нет в `all_config.yaml`                                      |
| `--vocab-map`      | Словарь, если словарь прогона отличается от представленных в [`api/vocab_maps/`](./vocab_maps) |
| `--task`           | Переопределить задачу, определённую по `data_path` в `all_config.yaml`                                                 |
| `--no-ema`         | Загрузить базовые веса, даже если есть тень EMA                                                |
| `--revision`       | Ветка, тег или коммит на Hugging Face                                                          |

Если передана директория прогона, берётся самый новый `step_N`, при наличии предпочитаются
веса EMA.

## Эндпоинты

| Метод | Путь        | Назначение                                    |
|-------|-------------|-----------------------------------------------|
| POST  | `/generate` | Один запрос или батч                          |
| GET   | `/info`     | Чекпоинт, задача, словарь, длина последовательности |
| GET   | `/health`   | Проверка живости                              |
| GET   | `/docs`     | Интерактивная документация OpenAPI            |

Запрос — это `{"task": ..., "input": ...}`, и `puzzle_id` для ARC; ответ повторяет форму запроса:

- `output` — это то, что выдала модель, с убранными паддингами;
- `steps` — глубина рекурсии, которую прошёл запрос, прежде чем его ACT-голова
сочла ответ готовым;
- `max_steps` — максимальное количество рекурсивных шагов.

## Формат входа по задачам

| Задача         | Вход                                                              |
|----------------|-------------------------------------------------------------------|
| `sudoku`       | 81 клетка построчно, `.` или `0` для пустых; пробелы игнорируются  |
| `maze`         | Квадратная сетка символов лабиринта: строками или одной строкой    |
| `arc`          | Сетка цветовых цифр, строки разделены `<eos>` или переносами       |
| `arithmetic`   | `3?5+2?7=42` — `?` отмечает каждый восстанавливаемый оператор      |
| `game_of_life` | `bbo$obb\|3` — паттерн, затем число поколений                       |

Для ARC дополнительно нужен `puzzle_id` — идентификатор задачи в нотации ARC-AGI
(`"007bbfb7"`), — он выбирает выученный puzzle-эмбеддинг. Допустимые идентификаторы берутся из
`identifiers.json`, который должен лежать рядом с `all_config.yaml`.

Примеры запросов для всех задач:

```bash
# sudoku
curl -s localhost:8080/generate -d '{"task": "sudoku", "input": "53..7....6..195....98....6.8...6...34..8.3..17...2...6.6....28....419..5....8..79"}'

# maze
curl -s localhost:8080/generate -d '{"task": "maze", "input": "S#   \n  ## \n# #  \n  ###\n   #G"}'

# arc
curl -s localhost:8080/generate -d '{"task": "arc", "input": "077<eos>777<eos>077", "puzzle_id": "007bbfb7"}'

# arithmetic
curl -s localhost:8080/generate -d '{"task": "arithmetic", "input": "3?5+2?7=42"}'

# game_of_life
curl -s localhost:8080/generate -d '{"task": "game_of_life", "input": "bbo$obb$bob|3"}'
```

## Длина последовательности

Каждый запрос дополняется до длины, на которой обучался прогон, поэтому значение должно быть
верным: неверное не приводит к ошибке, а превращает ответы в шум. Оно читается из
`all_config.yaml` либо передаётся флагом `--seq-len`, а лежит в `dataset.json` обучающего
датасета.

Примеры значений для датасетов, которые собирает этот репозиторий:

| Задача         | `seq_len` |
|----------------|-----------|
| `sudoku`       | 81        |
| `maze`         | 900       |
| `arc`          | 900       |
| `arithmetic`   | 19        |
| `game_of_life` | 243       |

## Словари

Id токенов — константы `dataset/build_*_dataset.py`, поэтому репозиторий поставляет словарь для
каждой задачи в [`api/vocab_maps/`](./vocab_maps). При желании словарь можно переопределить через `--vocab-map`.

## Чекпоинты с Hugging Face Hub

`--path_directory` принимает и идентификатор репозитория: он скачивается один раз и дальше
обрабатывается как локальная директория:

```bash
./host_model --path_directory sapientinc/HRM-checkpoint-sudoku-extreme --seq-len 81 --port 8080
```

`org/name` считается идентификатором репозитория только тогда, когда локально такого пути нет;
`hf://org/name` задаёт это явно. Такой репозиторий содержит только `all_config.yaml` и веса,
поэтому `--seq-len` обязателен, а код архитектуры берётся из `models/` этого репозитория, а не
из собственной копии чекпоинта.

## Несколько моделей сразу

Один процесс обслуживает один чекпоинт на одном GPU, поэтому на машине с несколькими картами
запускается по серверу на модель:

```bash
./host_model --path_directory checkpoints/sudoku/<run>     --device cuda:0 --port 8080 &
./host_model --path_directory checkpoints/arithmetic/<run> --device cuda:1 --port 8081 &
```

`CUDA_VISIBLE_DEVICES` тоже работает — тогда процесс видит свою карту как `cuda:0`.
